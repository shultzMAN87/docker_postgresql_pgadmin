## Как запускать

Папка `labs/` смонтирована в контейнер как `/labs`, поэтому удобнее всего запускать скрипты через `psql` внутри контейнера:

```bash
docker exec -it postgres psql -U postgres -d appdb -P pager=off -f /labs/gist/00_setup.sql
docker exec -it postgres psql -U postgres -d appdb -P pager=off -f /labs/gist/01_window_search.sql
```

Так вы видите вывод всех запросов скрипта сразу, включая `NOTICE`.

**В pgAdmin.** Откройте файл в Query Tool. pgAdmin при запуске всего скрипта показывает результат только последнего запроса, поэтому выделяйте нужный блок мышью и нажимайте F5. Сообщения `NOTICE` смотрите на вкладке Messages.

> Цифры в ваших планах будут немного отличаться от приведённых в ответах: данные случайные (хотя и с фиксированным `setseed`), а время зависит от машины. Смотрите на соотношения, а не на точные значения. Главная метрика — `Buffers` (сколько страниц по 8 КБ прочитано), она стабильнее времени.

## Как читать планы

- `Buffers: shared hit=N read=M` — страниц прочитано из кеша (`hit`) и с диска (`read`). Сумма — объём работы.
- `Index Only Scan` — данные взяты прямо из индекса, без обращения к таблице. `Heap Fetches: 0` значит, что таблицу не трогали совсем.
- `Bitmap Index Scan` + `Bitmap Heap Scan` — сначала по индексу собирается список страниц таблицы, потом они читаются.
- `Recheck Cond` и `Rows Removed by Index Recheck` — индекс выдал «кандидатов», и часть из них отсеяна проверкой по таблице. Это признак неточного индекса.
- `Order By: (p <-> ...)` у узла Index Scan — KNN-поиск: индекс сам отдаёт строки в порядке расстояния.
